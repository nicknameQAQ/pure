# 性能记录

2026-10-18，同机对比 0.2.0 与 pure 0.3.0。Windows 11 Home China；AMD Ryzen 7 7745HX with Radeon Graphics        ；内存 15 GiB。Electron 44.9.0。

## 方法

每版解压程序、单 EXE 各启动 10 次，使用全新独立配置目录。没有清空 Windows 文件缓存，也没有重启系统；因此不是严格的系统冷启动实验。测试期间不运行其他构建任务。

窗口指标是测试工具首次取得窗口连接的时间，正文指标额外等待可编辑正文和两帧渲染。单 EXE 使用相同的 CDP 连接流程，其数值包含解包与测试连接开销；比较软件初始化时应看两版解压程序。

每次解压版运行依次打开 2 万字、10 万字固定文档，各连续输入 10 次，记录输入提交到下一帧的耗时，并测试查找首个结果。千文件测试记录首次及再次快速打开。P95 使用 nearest-rank，启动样本为 10 次、输入样本为 100 次。

## 结果

时间单位为毫秒，每格为 **中位数 / P95**。变化按中位数计算，负数表示耗时降低。

| 指标 | 0.2.0 | pure 0.3.0 | 变化 |
| --- | ---: | ---: | ---: |
| 解压版：窗口可连接 | 303.4 / 1126.9 | 236.2 / 1045.8 | -22.2% |
| 解压版：正文可输入 | 675.3 / 1592.7 | 444.2 / 1500.6 | -34.2% |
| 单 EXE：正文可输入（含解包） | 4273.9 / 20510.6 | 3747.2 / 16687.1 | -12.3% |
| 首次打开 2 万字文档 | 218.2 / 451.5 | 210.1 / 229.3 | -3.7% |
| 随后打开 10 万字文档 | 122.8 / 236.8 | 95.2 / 142.3 | -22.4% |
| 2 万字：输入到下一帧 | 6.4 / 12.3 | 6.1 / 8.1 | -5.5% |
| 10 万字：输入到下一帧 | 18.1 / 22.1 | 6.1 / 8.1 | -66.3% |
| 2 万字：查找首个结果 | 102.1 / 112.8 | 105.4 / 111.6 | 3.2% |
| 10 万字：查找首个结果 | 138.1 / 145.8 | 123.5 / 138.1 | -10.6% |
| 千文件：首次快速打开查询 | 333.9 / 429.4 | 470.7 / 485.4 | 41.0% |
| 千文件：再次快速打开查询 | 78.8 / 96.3 | 20.4 / 24.4 | -74.1% |

正文可输入时全部 Electron 进程工作集：0.2.0 为 498.8 MiB（P95 505.2），pure 为 420.8 MiB（P95 423.4）。该值是一个时点的工作集，并非长期内存占用或峰值，不据此承诺内存下降。

## 改动与边界

- 源码编辑器、打印视图按需加载，生产代码压缩，启动入口直接挂载已加载模块，避免等待 Suspense 回退界面。
- 大目录仅渲染可见文件行；文件树、筛选和快速打开共享目录缓存及后台索引。
- 长文大纲和统计使用 Worker；查找缓存按文档与查询失效，移动光标不重新扫描全文。
- 单 EXE 仍需解包，因此默认推荐 ZIP 解压后运行。没有通过关闭安全隔离、公式或图表功能换取速度。
- 结果只代表本机和固定文档；杀毒软件、磁盘、字体、文档结构及首次资源加载均会影响耗时。首次千文件查询仍有回退，表中如实保留；重复查询改善明显，首次索引与弹窗的开销仍可继续优化。
